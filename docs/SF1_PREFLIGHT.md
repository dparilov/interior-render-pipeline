## 3. Actual Builder Behavior for `preserve`

### Code analysis: `render/workflow_builder.py`

**Key logic in `build()` method (lines 116-122):**

```python
if not mask_path or not ref_path:
    metadata['entities_skipped'].append({
        'name': name,
        'reason': 'missing mask or reference'
    })
    continue
```

### What happens for `render_mode: preserve`:

1. Entity has `reference: None` (per BUNDLE_SPEC: preserve entities don't need reference)
2. Builder checks `if not ref_path` → **TRUE**
3. Entity added to `entities_skipped` with reason "missing mask or reference"
4. `continue` → **no branch created**
5. Entity does NOT appear in:
   - `entities_applied`
   - `entity_order`
   - `entity_weights`
   - workflow graph nodes

### Behavior type: **NO BRANCH**

Entity is completely ignored. No nodes created for it.

## 4. Gap vs Spec

### BUNDLE_SPEC.md says:

> `preserve` — Entity excluded from generation entirely, geometry preserved as-is (e.g., window as light source)

### What builder actually does:

Entity is **excluded from workflow** because `reference: None`.

### Gap analysis:

| Aspect | Spec | Builder | Match? |
|--------|------|---------|--------|
| Excluded from generation | ✅ | ✅ | ✅ |
| Geometry preserved | Implicit | Not enforced | ⚠️ |
| No IPAdapter branch | ✅ | ✅ | ✅ |

**Minor gap:** The skip reason is "missing mask or reference" — not explicitly "render_mode: preserve". This is implementation detail, not functional gap.

### Recommendation:

Add explicit `render_mode` check for clarity:

```python
if entity.get('render_mode') == 'preserve':
    metadata['entities_skipped'].append({
        'name': name,
        'reason': 'render_mode: preserve'
    })
    continue
```

**Not blocking for SF1.**

## 6. Go / No-Go

### ✅ GO for SF1

**Rationale:**

1. Builder correctly skips `preserve` entities (no reference → no branch)
2. SF1 goal (test surfaces only) is achievable
3. No blocking gaps between spec and implementation

### Caveats:

1. **walls_upper and window regions are unconstrained** — they will be generated by the model without IPAdapter guidance. This is expected for SF1 (surfaces-only test).

2. Skip reason in metadata is "missing mask or reference" not "preserve" — cosmetic, not functional issue.

3. **No latent protection** for preserve regions — if preserve semantics require protecting these regions from generation, additional masking logic would be needed. Not required for SF1.
