# ComfyUI Render Skill

Генерация фотореалистичных интерьерных рендеров через локальный ComfyUI.

---

## Первый вопрос

Если из контекста непонятно, спроси:

```
У тебя уже есть готовое ТЗ в формате (путь к ТЗ.md), или собираем новое с нуля?

1. **Есть готовое** → скинь путь, я запущу рендер
2. **Собираем новое** → расскажи что за проект, пришли скетчи и референсы
```

---

## Сбор ТЗ от пользователя

Перед запуском рендера нужно собрать полное ТЗ. Не запускай рендер пока не собрана вся информация!

### Что нужно получить:

| # | Категория | Что собрать | Обязательно |
|---|-----------|-------------|-------------|
| 1 | **Скетчи** | Планировка/эскиз помещения (jpg/png) | ✅ ДА |
| 2 | **Референсы материалов** | Фото плитки, покрытий, отделки | ✅ ДА |
| 3 | **Референсы предметов** | Фото мебели, сантехники, декора | ✅ ДА |
| 4 | **Фактуры** | Текстура материалов для каждого элемента | Желательно |
| 5 | **Освещение** | Тип и настроение света | ✅ ДА |
| 6 | **Референс освещения** | Фото с нужной атмосферой/светом | Желательно |
| 7 | **Ракурсы** | Какие виды нужны | ✅ ДА |
| 8 | **Время суток** | Влияет на свет и тени | Желательно |
| 9 | **Ограничения** | Что нельзя менять | Желательно |
| 10 | **Референс атмосферы** | Пример готового рендера/фото | Желательно |

### Детали по категориям:

#### Освещение (спроси если не указано):
| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| **Естественное дневное** | Мягкий свет из окна, голубоватые тени | Светлые интерьеры |
| **Естественное вечернее** | Тёплый золотистый, длинные тени | Уютная атмосфера, golden hour |
| **Студийное** | Равномерное, минимум теней | Каталожная съёмка, чёткие детали |
| **Акцентное** | Точечные источники, драматичные тени | Арт-объекты, акценты |
| **Смешанное** | Окно + искусственный свет | Реалистичные жилые интерьеры |

#### Референс освещения (NEW):
Если есть фото с нужной атмосферой — добавь его в ТЗ:
- Захватывает цветовую температуру (тёплый/холодный)
- Переносит контраст и мягкость теней
- Задаёт общее настроение
- **Вес:** 0.3 (влияет на атмосферу, не перебивает предметы)

Примеры хороших референсов:
- Фото интерьера с нужным светом
- Кадр из фильма с похожей атмосферой
- Журнальное фото с желаемой обработкой

#### Ракурсы (уточни приоритет):
| Ракурс | Для чего |
|--------|----------|
| **Фронтальный** | Главная стена, основная композиция |
| **Угловой 45°** | Объём пространства, глубина |
| **Сверху (план)** | Расположение мебели |
| **Детальный** | Крупный план зоны/предмета |
| **От входа** | Первое впечатление |

#### Время суток:
| Время | Эффект на рендер |
|-------|-----------------|
| **Утро (8-10)** | Свежий свет, длинные мягкие тени |
| **День (12-14)** | Яркий свет, короткие тени |
| **Вечер (17-19)** | Тёплый свет, golden hour |
| **Ночь** | Искусственный свет, уют |

#### Фактуры материалов:

Фактура указывается **отдельно от референса** и добавляется в промпт. Это позволяет уточнить текстуру даже если референс не идеален.

| Категория | Примеры фактур |
|-----------|----------------|
| **Ткани** | лён, хлопок, бархат, велюр, махра, шёлк, мешковина |
| **Керамика** | матовая, глянцевая, сатиновая, рельефная, под камень |
| **Металл** | полированный хром, матовый никель, брашированная сталь |
| **Дерево** | гладкое лакированное, брашированное, состаренное |
| **Камень** | полированный мрамор, матовый гранит, травертин |
| **Пластик/акрил** | глянцевый, матовый, прозрачный |

**Как спрашивать:**
```
Для [элемент] — есть требования к фактуре?
Например: штора из льна, полотенца махровые, плитка матовая?
```

**Формат в ТЗ:**
```markdown
### Штора для ванны
- **Референс:** `референсы/curtain.jpg`
- **Фактура:** льняная ткань с лёгкой текстурой
- **КРИТИЧНО:** НЕТ
```

#### Референс атмосферы:
Если есть — попроси фото/скриншот похожего рендера или реального интерьера с нужным настроением. Это сильно помогает понять ожидания.

#### Цветовая гамма:
| Тип | Описание | Примеры |
|-----|----------|---------|
| **Тёплая** | Жёлтые, оранжевые, коричневые тона | Уютные интерьеры, дерево, закат |
| **Холодная** | Синие, серые, белые тона | Утренний свет, чистота |
| **Нейтральная** | Бежевые, серые, сбалансированная | Современная классика |
| **Контрастная** | Сочетание тёплых и холодных | Акцентные стены, драма |

#### Насыщенность цвета:
| Тип | Эффект |
|-----|--------|
| **Сочные/яркие** | Живой, энергичный интерьер |
| **Пастельные** | Мягкий, расслабленный |
| **Приглушённые** | Элегантный, сдержанный |
| **Монохром** | Один цвет в разных оттенках |

#### Контраст и тени:
| Тип | Когда использовать |
|-----|-------------------|
| **Мягкий** | Уютная атмосфера |
| **Средний** | Универсальный, реалистичный |
| **Драматичный** | Контрастный, акцентное освещение |

#### Глубина резкости:
| Тип | Эффект |
|-----|--------|
| **Всё в фокусе** | Каталожное фото, все детали видны |
| **Размытый фон** | Акцент на переднем плане |
| **Tilt-shift** | Миниатюрный эффект |

#### Поверхности и отражения:
| Вопрос | Зачем |
|--------|-------|
| "Много глянцевых поверхностей?" | Отражения добавляют реализма |
| "Зеркала в кадре?" | Сложные отражения |
| "Матовые или глянцевые стены?" | Влияет на блики |

#### Текстуры (акценты):
| Материал | Как описать в промпте |
|----------|----------------------|
| Дерево | "visible wood grain texture" |
| Камень | "natural stone texture, veining" |
| Ткань | "soft fabric texture, folds" |
| Металл | "brushed metal, chrome reflection" |
| Бетон | "raw concrete texture" |

#### Негативный промпт (чего избегать):
Спроси: "Что точно НЕ должно появиться на рендере?"

Типичные исключения:
- Люди, животные
- Определённые цвета
- Лишние предметы
- Стилистические элементы которые не нужны

### Алгоритм сбора:

**Шаг 1: Запроси базу**
```
Для создания рендера мне нужно:

1. **Скетч/планировка** — эскиз помещения с расположением предметов
2. **Референсы материалов** — фото плитки, краски стен, пола
3. **Референсы предметов** — фото мебели, сантехники, декора
4. **Фактуры** — есть ли особые требования к текстуре? (лён, бархат, матовая керамика...)
5. **Освещение** — дневное из окна, вечернее тёплое, студийное?

Пришли что есть, я скажу чего не хватает.
```

**Шаг 2: Проанализируй и валидируй каждый референс**

Для каждого изображения определи:
- Это скетч или референс?
- Какой элемент изображён?
- Достаточно ли качество для IP-Adapter?

#### Валидация референсов:

Проверь каждый референс по критериям:

| Критерий | Хорошо | Проблема | Рекомендация |
|----------|--------|----------|--------------|
| **Разрешение** | >512×512 | <300px по стороне | "Референс слишком мелкий, IP-Adapter может не уловить детали. Есть версия покрупнее?" |
| **Фокус** | Предмет чёткий | Размыто, не в фокусе | "Референс размытый. Лучше найти чёткое фото" |
| **Ракурс** | Предмет виден целиком | Обрезан, частично | "Виден не весь предмет. Это может исказить пропорции" |
| **Фон** | Нейтральный или предмет выделяется | Много лишних объектов | "Много отвлекающих элементов. Модель может захватить лишнее" |
| **Освещение** | Равномерное | Пересвет/недосвет | "Сильные тени/блики могут перенестись в рендер" |
| **Цвет** | Естественный | Фильтры, искажения | "Цвет выглядит искажённым. Это реальный цвет предмета?" |

**Формат предупреждения:**
```
⚠️ Референс [название]: [проблема]
Рекомендация: [что лучше]
Продолжаем с этим референсом или поищем другой?
```

**Если пользователь подтверждает** — принимаем референс, но отмечаем в ТЗ как "⚠️ субоптимальный".

**Шаг 3: Запроси недостающее**

Типичные вопросы:
- "Какого цвета должна быть тумба? Пришли фото конкретной модели"
- "На скетче вижу душевую — есть референс смесителя/лейки?"
- "Стены — плитка или краска? Нужен референс"
- "Какие элементы КРИТИЧНЫ и должны быть узнаваемы на 100%?"
- "Есть особые требования к фактуре/текстуре? (например: штора с льняной фактурой, полотенца из махры)"

**Шаг 4: Уточни визуальные параметры**
```
Несколько вопросов для точности:

🧵 Фактуры:
- Есть особые требования к текстурам?
- Примеры: штора из льна, полотенца махровые, плитка матовая
- Для каких элементов это важно?

📸 Освещение:
- Естественное дневное (из окна)?
- Вечернее тёплое (golden hour)?
- Студийное (равномерное, для каталога)?
- Акцентное (точечные источники)?
- **Есть фото с нужной атмосферой?** (референс освещения)

🎨 Цветовая гамма:
- Тёплая (жёлтые, коричневые)?
- Холодная (синие, серые)?
- Нейтральная?

🌈 Насыщенность:
- Сочные яркие цвета?
- Пастельные приглушённые?

⚡ Контраст:
- Мягкий?
- Драматичный?

✨ Поверхности:
- Много глянца и отражений?
- Матовые поверхности?

🔍 Фокус:
- Всё чётко (каталог)?
- Акцент на зоне (размытый фон)?

🚫 Негативный промпт — чего НЕ должно быть:
- Люди/животные?
- Определённые цвета?
- Лишние предметы?

💡 Есть референс атмосферы? (фото с нужным настроением)
```

**Шаг 5: Подтверди понимание**

Перед созданием ТЗ покажи summary:
```
Понял задачу:
- Помещение: ванная 4м²
- Стиль: современный, светлый
- Критичные элементы: плитка пола (синяя), тумба (тёмно-серая), смеситель (хром)
- Референсов получено: 6 шт
- Скетчей: 1 шт (фронтальный вид)

Всё верно? Создаю ТЗ и запускаю рендер.
```

### Проверка полноты референсов (ОБЯЗАТЕЛЬНО перед созданием ТЗ):

**Шаг 1: Проанализируй скетч**

Посмотри на скетч и составь список ВСЕХ видимых предметов/поверхностей:
```
На скетче вижу:
- Пол (материал?)
- Стены (плитка/краска?)
- Тумба под раковину
- Раковина
- Смеситель
- Зеркало
- Душевая зона
- Ванна
- Полотенцесушитель
- [и т.д.]
```

**Шаг 2: Сопоставь с полученными референсами**

Для каждого элемента из списка:
- ✅ Есть референс → ОК
- ⚠️ Нет референса → ПРЕДУПРЕДИТЬ

**Шаг 3: Явно сообщи о пропусках**
```
🔍 Анализ полноты референсов:

✅ Есть референсы (6):
- Напольная плитка
- Настенная плитка  
- Тумба
- Смеситель
- Зеркало
- Полотенцесушитель

⚠️ НЕТ референсов (2):
- **Ванна** — на скетче есть, референс не предоставлен
- **Корзина для белья** — на скетче есть, референс не предоставлен

Для элементов без референсов модель сгенерирует "заглушку" — 
типичный предмет этой категории, но без контроля над внешним видом.

Варианты:
1. Предоставить референсы для этих элементов
2. Подтвердить что заглушки ОК
3. Убрать эти элементы из скетча
```

**Не запускай рендер** пока пользователь явно не выбрал вариант для каждого пропущенного элемента!

## Использование

```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py --tz /path/to/project/ТЗ.md
```

Скрипт автоматически:
1. Парсит ТЗ.md
2. Находит все референсы по путям из ТЗ
3. Строит workflow с IP-Adapter для каждого референса
4. Логирует всё что использовал

## Формат ТЗ

ТЗ должно быть в формате Markdown в папке проекта.

### Структура папки проекта

```
~/ComfyUI/input/<project_name>/
├── ТЗ.md                    # Техническое задание
├── скетчи/
│   ├── front.jpg            # Фронтальный вид
│   ├── angle.jpg            # Вид под углом
│   └── top.jpg              # Вид сверху
└── референсы/
    ├── floor_tiles.jpg      # Напольное покрытие
    ├── wall_tiles.jpg       # Настенная плитка
    ├── vanity.jpg           # Мебель
    └── ...                  # Другие элементы
```

### Формат ТЗ.md

```markdown
# ТЗ: [Название проекта]

## Общее описание
[Описание проекта, стиль, атмосфера]

## Скетчи
| Ракурс | Файл | Описание |
|--------|------|----------|
| Название | `скетчи/file.jpg` | Описание |

**Для первого рендера использовать:** `скетчи/front.jpg`

## Материалы и предметы

### [Название элемента]
- **Модель:** [название]
- **Описание:** [цвет, материал, особенности]
- **Референс:** `референсы/filename.jpg`
- **Фактура:** [опционально — текстура материала]
- **КРИТИЧНО:** ДА/НЕТ

[Повторить для каждого элемента]

**Примеры фактур:**
- "льняная ткань" / "linen texture"
- "матовая керамика" / "matte ceramic"
- "полированный хром" / "polished chrome"

## Референс освещения
- **Файл:** `референсы/lighting.jpg`
- **Описание:** [Мягкий дневной свет / тёплый вечерний / студийное и т.д.]

(Опционально — фото с желаемой атмосферой и светом. Влияет на цветовую температуру и настроение, вес 0.3)
- "шероховатый бетон" / "raw concrete"
- "мягкий велюр" / "soft velvet"

## Ограничения
[Что нельзя менять, что не должно появиться]

## Стиль рендера
[Освещение, атмосфера, качество]
```

### Важные правила парсинга

- Референс указывается в формате: `**Референс:**` `референсы/filename.jpg``
- Фактура указывается в формате: `**Фактура:** льняная ткань`
- Критичные элементы помечаются: `**КРИТИЧНО:** ДА`
- Первый скетч указывается: `**Для первого рендера использовать:**` `скетчи/file.jpg``

**Фактура добавляется в промпт** для элемента и усиливает текстурное описание независимо от референса.

## Параметры скрипта

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--tz` | обязательный | Путь к ТЗ.md |
| `--output` | из имени проекта | Префикс выходного файла |
| `--steps` | 50 | Количество шагов |
| `--cfg` | 7.5 | CFG scale |
| `--cn-strength` | 0.4 | ControlNet strength |
| `--ip-strength` | 0.85 | Базовый IP-Adapter strength |

## 🧪 Тестовый запуск (РЕКОМЕНДУЕТСЯ для нового проекта)

**Перед полным рендером сделай тестовый с минимумом шагов!**

```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py --tz /path/to/ТЗ.md --steps 5
```

Это позволяет:
- Проверить что весь pipeline работает (все модели грузятся, референсы читаются)
- Быстро увидеть примерный результат (~5-7 минут вместо 40)
- Выявить ошибки до долгого рендера

**Если тест прошёл** — запускай полный:
```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py --tz /path/to/ТЗ.md --steps 50
```

## Веса IP-Adapter

Скрипт автоматически назначает веса по важности:

|---------|-------------|-------------------|

## ⚠️ МОНИТОРИНГ — НЕ БЛОКИРУЙ СЕССИЮ!

**НИКОГДА не используй `process poll` с timeout > 10 секунд!**

Долгий poll блокирует агента и пользователь не может достучаться.

### Правильный подход:

1. **Запусти процесс** — `nohup python comfyui-render.py ... &`
2. **Сразу ответь пользователю** — "Запущено, ~35 мин до готовности"
3. **Проверяй прогресс только когда спросят:**
   ```bash
   tail -1 /tmp/comfyui.log | grep -oP '\d+%' | tail -1
   ```
4. **Не висни в ожидании** — никаких `sleep 300` или `poll timeout=300000`

### Как узнать что готово:

```bash
# Проверить очередь
curl -s http://127.0.0.1:8188/queue | python3 -c "import json,sys; d=json.load(sys.stdin); print(f'Running: {len(d.get(\"queue_running\",[]))} | Pending: {len(d.get(\"queue_pending\",[]))}')"

# Если Running: 0, Pending: 0 — готово или ошибка

```

## Режимы рендеринга

### 1. Без Refiner (быстро, безопасно)
```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py \
  --tz ~/ComfyUI/input/project/ТЗ.md \
  --no-refiner
```
- RAM: ~22GB пик
- Время: ~35 мин
- Качество: хорошее, но менее детализированное

### 2. Two-pass (максимум качества, безопасно)
Разделяет генерацию на 2 этапа чтобы не держать все модели в RAM одновременно.

**Pass 1 — Base + IP-Adapter:**
```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py \
  --tz ~/ComfyUI/input/project/ТЗ.md \
  --two-pass --pass 1
```
- Генерирует основу с IP-Adapter
- Сохраняет latent в файл
- Выводит превью `*_pass1.png`

**Подожди завершения!** Затем:

**Pass 2 — Refiner:**
```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py \
  --tz ~/ComfyUI/input/project/ТЗ.md \
  --two-pass --pass 2
```
- Загружает latent из Pass 1
- Применяет Refiner
- Выводит финальный `*_render.png`

**Почему two-pass:**
- Pass 1: SDXL (~10GB) + IP-Adapter (~4GB) + ControlNet (~5GB) = ~22GB
- Между pass'ами модели выгружаются
- Pass 2: Refiner (~6GB) + VAE (~1GB) = ~7GB
- Пиковое потребление **никогда не превышает 22GB**

### 3. Single-pass (рискованно на 29GB RAM)
```bash
python3 ~/.openclaw/workspace/ops/comfyui-render.py \
  --tz ~/ComfyUI/input/project/ТЗ.md
```
⚠️ **Не рекомендуется!** Требует ~28GB RAM, может упасть OOM.

**После завершения/падения** — проверь лог монитора:
```bash
tail -20 /tmp/sysmon.jsonl
```
